四、黑骑士完整状态机
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

黑骑士的正常循环严格按照以下顺序执行。

不得随机打乱。

阶段 1：诅咒发放

- 不造成伤害。
- 向玩家抽牌堆加入 5 张【幽冥诅咒】。
- 卡牌应被洗入抽牌堆，而不是直接进入手牌。
- 播放诅咒施法动画和紫色、红色或幽魂色粒子特效。
- 显示清晰的非攻击意图。

阶段 2：斜劈

- 对玩家造成 25 点普通可格挡伤害。
- 播放斜向挥斧动画。
- 使用独立的斜向刀光特效。
- 显示攻击意图和最终伤害值。

阶段 3：斜劈

- 再次造成 25 点普通可格挡伤害。
- 与阶段 2 使用同一种攻击规则。
- 动画可以镜像或略有变化，但不能改变伤害规则。

阶段 4：横砍

- 对玩家造成 34 点普通可格挡伤害。
- 播放水平方向的大范围挥斧动画。
- 如果本次攻击没有被完全格挡，即玩家实际损失的生命值大于 0：
  - 向玩家抽牌堆加入 1 张游戏已有的【伤口】。
- 如果玩家完全格挡，不能加入伤口。
- 判断依据是本次攻击最终造成的实际生命伤害，而不是攻击前的格挡数值。
- 显示攻击意图和最终伤害值。

阶段 5：竖劈+

- 基础伤害为 43。
- 默认是无法被格挡的特殊伤害。
- 默认情况下必须绕过普通格挡，但仍然通过合法的游戏伤害系统结算。
- 不要错误地使用普通攻击后再手动扣除第二次生命。
- 播放明显的高举斧头、短暂停顿、向下重劈动画。
- 使用竖直刀光、地面冲击和屏幕震动。
- 意图必须明确显示这是“不可格挡”的攻击。

但是，如果玩家在当前回合满足【幽冥诅咒】规则，则：

1. 这一次竖劈从“不可格挡伤害”转换为“普通可格挡伤害”。
2. 该保护只作用于这一次竖劈。
3. 竖劈结算后立即消耗保护状态。
4. 黑骑士恢复等同于本次攻击实际造成生命伤害的生命值。
5. 黑骑士恢复量不能超过最大生命值。
6. 如果竖劈被完全格挡，实际生命伤害为 0，黑骑士恢复 0。
7. 恢复量不能按照面板伤害或格挡前伤害计算。
8. 如果玩家没有打出幽冥诅咒，竖劈保持不可格挡，并且不触发这条治疗效果。

如果力量提高攻击伤害，治疗仍然按照最终实际生命伤害计算。

阶段 6：暗鬼铠甲

首先计算玩家方当前存活的战斗实体数量 N。

玩家方实体包括：

- 所有存活玩家角色
- 所有存活的玩家召唤物
- 其他实际参与战斗、属于玩家阵营的实体

不包括：

- 卡牌
- 意图图标
- 特效节点
- UI 节点
- 已死亡实体
- 临时视觉残影

效果：

- 黑骑士获得 50 × N 点格挡。
- 玩家获得 N 层【怯懦】。

示例：

玩家本体 1 个，召唤物 2 个，则 N = 3：

- 黑骑士获得 150 点格挡。
- 玩家获得 3 层怯懦。

单人模式对当前玩家施加 N 层怯懦。

如果当前版本存在多人模式，则对每一名存活玩家角色施加 N 层怯懦，代码中需要清晰封装，便于后续调整。

播放：

- 黑色、银色、紫色护甲凝聚效果
- 护盾吸收动画
- 怯懦 Debuff 图标和获得动画

阶段 7：强化——真身

黑骑士进入真身强化阶段。

效果：

1. 在黑骑士背后显现一个巨大的半透明黑骑士幽影。
2. 幽影可以只展示头部、肩甲、胸甲、手臂和部分巨斧。
3. 幽影需要明显大于主体。
4. 幽影不能拥有单独碰撞体，不能成为独立攻击目标。
5. 黑骑士永久获得 5 点力量。
6. 力量允许正常叠加。
7. 在同一个【强化——真身】状态内，完整重施阶段 1【诅咒发放】的效果：
   - 向每名存活玩家的抽牌堆洗入 5 张【幽冥诅咒】
   - 每实际成功洗入 1 张，黑骑士获得 1 层【噬命诅印】
   - 显示【强化——真身】与【诅咒发放 5】两个复合意图
   - 不新增中间状态 ID，保持 `BK_TRUE_FORM` 的存档兼容性
8. 接下来的三次行动固定变成：

   横砍 → 横砍 → 竖劈+

9. 这三次攻击继续使用原本的完整规则：
   - 横砍未完全格挡时加入伤口
   - 竖劈默认不可格挡
   - 打出幽冥诅咒后竖劈变为可格挡，并按实际生命伤害治疗黑骑士
10. 三次攻击执行完毕后：
   - 真身幽影消散
   - 返回阶段 1【诅咒发放】
   - 重新开始整个循环

完整循环为：

诅咒发放
→ 斜劈
→ 斜劈
→ 横砍
→ 竖劈+
→ 暗鬼铠甲
→ 强化——真身
→ 横砍
→ 横砍
→ 竖劈+
→ 返回诅咒发放

状态机必须能够正确处理：

- 战斗保存和读取
- 玩家死亡
- 黑骑士死亡
- 中途跳过行动
- 眩晕或其他导致敌人无法行动的状态
- 力量变化
- 黑骑士被打断
- 多次循环
- 动画被快速跳过
- 战斗重新开始

五、幽冥诅咒卡
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

中文名称：幽冥诅咒
英文名称：Nether Curse

卡牌类型：

- 状态牌
- 费用 1
- 可以主动打出
- 不升级
- 默认不消耗
- 默认不虚无
- 默认不保留
- 打出后正常进入弃牌堆，除非该卡牌实例已被怯懦赋予消耗

效果文本：

“移除黑暗骑士 1 层噬命诅印。”

具体规则：

1. 保留原有费用、可打出方式与弃牌生命周期。
2. 黑暗骑士没有噬命诅印时不发生效果，层数不会变成负数。
3. 每次只移除 1 层，由卡牌的联机动作链统一结算。
4. 竖劈是否不可格挡不再由打出此牌决定；改为在各玩家回合结束时检查其手牌中是否有幽冥诅咒。

六、怯懦 Debuff
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

中文名称：怯懦
英文名称：Cowardice

类型：

- 玩家 Debuff
- 可叠层
- 层数必须保存
- 提供图标、名称、描述和战斗提示

效果：

“接下来抽到的 X 张幽冥诅咒获得消耗。”

精确规则：

1. 玩家拥有 N 层怯懦时，每当一张幽冥诅咒进入玩家手牌：
   - 仅让这一个卡牌实例获得【消耗】。
   - 怯懦层数减少 1。
2. 每抽到一张幽冥诅咒，最多消耗 1 层怯懦。
3. 怯懦不能修改卡牌基础定义。
4. 其他幽冥诅咒实例不能因为一个实例被修改而同时获得消耗。
5. 怯懦层数降至 0 时移除 Debuff。
6. 普通卡牌被抽入手牌时不能消耗怯懦层数。
7. 通过以下方式进入手牌的幽冥诅咒也应触发：
   - 正常抽牌
   - 从抽牌堆直接取出
   - 搜索后加入手牌
   - 其他正式的“进入手牌”事件
8. 如果卡牌因为手牌已满而进入弃牌堆，不应错误消耗怯懦层数，除非游戏的正式事件定义认为其已经进入手牌。
9. 卡牌获得消耗后，在本次战斗内保留该实例的修改。
10. 战斗结束后不应永久修改卡牌原型。

描述中动态显示剩余层数。

- 保留源文件和生成脚本
- 输出适合当前 Godot 导入流程的 PNG
- 如果使用图集，保留图集生成配置

九、动画
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

先检查当前游戏和模组运行环境支持的动画方案。

优先使用：

- 游戏现有的敌人动画抽象
- Spine Runtime
- Godot AnimationPlayer
- Skeleton2D
- Bone2D
- Sprite2D 分层节点
- Tween
- Shader
- GPUParticles2D 或 CPUParticles2D

如果没有 Spine 编辑器或无法合法生成 .skel 文件，不要伪造 Spine 二进制资源。

此时改用 Godot 原生 Skeleton2D、AnimationPlayer 或分层 Sprite2D，确保动画可以直接运行。

必须实现以下动画状态：

1. Idle
2. CurseCast
3. DiagonalSlashA
4. DiagonalSlashB
5. HorizontalSlash
6. VerticalSlash
7. DarkArmor
8. TrueFormEnter
9. TrueFormIdle
10. TrueFormExit
11. Hurt
12. Death

Idle：

- 循环时长约 2.5～3.5 秒
- 整体缓慢上下悬浮
- 身体有小幅度倾斜
- 肩甲和手臂存在延迟运动
- 披风缓慢摆动
- 下半身幽魂尾迹持续流动
- 面部红光周期性变化
- 巨斧存在轻微惯性运动
- 不出现腿部动作

斜劈：

- 明确的蓄力
- 身体向后收缩
- 斧头斜向快速挥动
- 命中帧有短暂顿帧
- 产生斜向刀光
- 命中事件与实际伤害结算同步
- 不能在动画还未命中时提前扣血

横砍：

- 使用较大的水平挥动弧线
- 身体和披风产生反方向惯性
- 产生宽范围刀光
- 命中后触发伤口判定
- 刀光不能遮挡全部角色

竖劈：

- 斧头高举
- 明显的攻击预备时间
- 快速向下重劈
- 命中瞬间短暂停顿
- 屏幕震动
- 竖直刀光
- 冲击波
- 幽魂碎片
- 伤害事件与命中帧同步
- 可格挡和不可格挡版本可以共用主体动画，但必须使用不同意图和命中特效

暗鬼铠甲：

- 玩家方实体处出现被抽取的幽魂能量
- 能量流向黑骑士
- 黑骑士周围生成护盾
- 护盾数值在吸收完成时结算
- 怯懦图标在玩家侧出现

真身：

- 巨大幽影从黑骑士背后上升
- 幽影保持半透明
- 幽影具有轻微延迟运动
- 幽影不与主体完全重合
- 真身阶段的三次攻击中幽影应继续存在
- 真身阶段结束后逐渐消散
- 幽影不能成为独立实体

死亡：

- 黑骑士失去悬浮力
- 盔甲轻微下沉或裂开
- 红色面部光熄灭
- 幽魂从盔甲中逸出
- 披风和灵魂尾迹消散
- 动画结束后再触发正式死亡清理

建立一个独立的动画预览场景或开发工具，可以逐个播放所有动画，不需要每次进入完整战斗才能检查。

十、攻击和状态特效
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

必须制作独立于角色主体动画的特效：

- 斜劈刀光
- 横砍刀光
- 竖劈刀光
- 地面冲击
- 命中闪光
- 幽魂粒子

- 真身显现烟雾
- 黑骑士治疗时的生命吸收轨迹
- 幽冥诅咒保护生效时的附着效果

- 紫色
- 暗红色
- 银白色
- 黑色
- 参考图中的绿色幽魂色

为主。

避免过度明亮的现代科幻激光风格。

粒子和 Shader 参数必须集中配置，方便以后调整。

如果可以生成原创程序化音效，则至少生成：

- 斧头挥动
- 斧头命中
- 竖劈重击
- 诅咒施法
- 真身显现

如果音频生成会严重阻碍主要功能，则优先保证战斗、动画和视觉特效完整，并在最终报告中明确说明。

- 获得 5 力量。

- 幽影正确出现和消失。

测试 13：多循环
- 状态机执行两次完整循环后没有错位。

测试 14：第一战覆盖
- Debug 开启时只替换第一幕第一场普通战斗。
- Debug 关闭后不替换。

测试 15：死亡和清理
- 黑骑士死亡后停止状态机。
- 真身、粒子和动画节点被正确清理。
- 战斗可以正常结算。

- 如果游戏支持战斗内保存，重新载入后阶段、真身剩余攻击数、怯懦和保护标记正确恢复。
